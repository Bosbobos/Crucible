# 06. Поручение кодовому агенту

## Готовое поручение

Развивай **существующий репозиторий**, не создавай отдельное приложение. Прочитай `00_START_HERE.md` пакета `Crucible_Implementation_Pack_v3` и активные документы; `archive/` не исполняй. Владелец ещё не выполнял прежние задания: наличие ТЗ не доказывает наличие кода.

Цель: светлый Crucible / «Белый Атлас», неизменный task-first учебный процесс, отдельный **character-service** для всей косметической RPG-прогрессии и настоящий 2D paper-doll. Встроенная LLM, боёвка, валюта, loot randomization, новые учебные ограничения, новый renderer-service и переписывание учебного ядра не нужны.

Выполни G0–G8 ниже в текущем стеке. Начни с аудита и первого исполняемого вертикального среза, а не заканчивай ответом с очередным общим планом. Архитектурные решения `05`/`09` обязательны: учебные факты и scheduler остаются у предметных владельцев, RPG получает их асинхронно, владение XP/inventory/loadout — у нового сервиса. Если реальная граница несовместима с репозиторием, покажи конкретный технический конфликт и адаптер, не возвращай молча старое хранение RPG в learning-service.

Пять референсов брони и база уже вложены. Сопоставление `Tier_1→ARM-00`, `Tier_0→ARM-01` сознательное. BASE содержит короткую повязку: скрывай её маской при отрисовке legs, не требуй нового голого персонажа. Пример меча — отдельный дизайн/pose reference; для хвата нужна локальная hand representation, а не новая вся рука. Финальный ARM-05 отсутствует.

Изображения генерирует владелец **по одному** по `art_prompts/`. Не запускать генератор из процесса модернизации и не ждать всего арт-каталога. Где изображения/слои не готовы, используй честные category placeholders и сохраняй реальные состояния предметов. Нарезку/маски/rig выполняй из вложенных source files; готовый полнофигурный source не выдавай за independent slots. Маски отсутствующих изображений не применяй.

Сохрани данные, существующий renderer формул, draft saving, auth, API и учебную методику. Не стирай историю, не складывай legacy XP с пересчитанным за те же факты. Synthetic fixtures — только отдельный demo/test profile. Не вводи mock XP в настоящий профиль. Все новые определения и API проходят validation/tests.

После каждого этапа сообщай: что действительно изменено, реальные тесты и их результат, evidence paths, что осталось или заблокировано. Статусы `passed / failed / not_run`; отсутствие настоящего арта/контента — самостоятельные статусы, не скрытая причина остановки всего проекта. Остановись после обязательных сценариев, не расширяй игру.

## G0. Аудит и безопасная точка возврата

Прочитай AGENTS.md и инструкции репозитория. Проверь git status, незакоммиченные/неотслеживаемые файлы, действующие сервисы/порты, DB ownership, migrations, auth, frontend/UI library, математический renderer, event transport, exporter/MCP и текущие XP/inventory, если они вообще есть. Никаких destructive clean/reset.

Сохрани baseline запуска и учебного маршрута; сделай резервную копию по принятым в репозитории правилам и тестовую ветку. Не публикуй личные данные/секреты.

**Выходы:** `docs/crucible/audit.md`, `architecture-mapping.md`, `migration-plan.md`, `content-gaps.md`, `asset-audit.md`. Mapping: требование → реальный owner/file/API → изменение → риск/тест. Отдельно перечисли, каких файлов/data из старого пакета не было; текущий пакет их не считает существовавшими.

**Gate:** учебный baseline запускается или существующая ошибка воспроизведена и отделена от модернизации; выбран один способ безопасной доставки RPG-фактов; source hashes сопоставлены. Если какая-то инструкция/инфраструктура недоступна, продолжай независимые части и явно фиксируй блокер.

## G1. Новый сервис и definitions

Добавь character-service в существующий compose/build/deployment без новой платформы. Изолируй его роль/схему БД, миграции и versioned definitions. API/worker могут быть отдельными процессами одного доменного сервиса. Не переносить туда условие задач, авторизацию или scheduler.

Импортируй `data/progression.json`, `items.json`, `ranks.json`, `sets.json`, `volumes.json`, `trial_blueprints.json`; добавь строгие схемы/валидаторы в используемом языке. Реализуй pure domain progression, lifecycle publications, summary API и ошибки. На ранней стадии synthetic fixtures допустимы только в тестах/stories.

**Gate:** 60 порогов; 59 уникальных определений предметов/косметики; 6 рангов; 25 томов; 58 чертежей; стартовые ownership; migration up/rollback на disposable БД. Никакого автоматического live replay старой истории.

## G2. Учебный факт → надёжная RPG-проекция

Выбери один действительный учебный сценарий. Запись результата + source outbox атомарны у владельца; delivery имеет retries; consumer пишет inbox/fact/entitlement/ledger/summary в своей транзакции. Определи immutable source metadata, revisions и correction contract. Запусти duplicate/out-of-order/revocation тесты и event flow с недоступным character-service.

**Gate:** реальная попытка сохраняется при остановленном RPG; после запуска consumer начисляется ровно один объяснимый результат. Сильнейшая попытка в equivalence group платит разницу, коррекция делает compensating delta. Нет browser endpoint «дай XP».

**Evidence:** один actual end-to-end trace по correlation ID без секретов; два разных event IDs одного факта; crash-before/after-commit; восстановление backlog.

## G3. Светлая тема и учебные экраны — параллельно G1/G2

Внедри `styles/crucible-tokens.css`, Onest/Cormorant либо документированное совместимое отклонение, одну icon system. Сначала общие кнопки/поля/навигация, затем «Сегодня», «Задача», «Ядро/Теория/Лаборатории». Сохрани функциональность, чистую математику, draft/attempt continuity. Удали прежнюю градиентную SaaS-тему, не заменяй зелёное свечение золотым.

**Gate:** 4 viewport, zoom 200%, keyboard route, long formula, reduced motion, сохраняемые состояния, возврат к попытке. Уже здесь допустим релиз учебного UI с честными декоративными placeholders. Не ждать финального ARM-05.

## G4. Инвентарь, путь, предметы и деградация

Свяжи реальные summary/catalog/path/loadout API. Реализуй ownership, unlock explanations, atomic equip с expected revision, preview без записи, `none` и preferences. Все девять slots предусмотрены. Настоящие V/E/R/K/M считаются только из доступных подтверждённых evidence; unknown mapping = blocked_content. На «Пути» нет fake passed.

Галерея пяти полных сетов разрешена с явной подписью. Реликвии — девять позиций. Меч и задний орнамент имеют приоритет визуального подключения, щит/мантия могут оставаться placeholders. Missing art не блокирует сохранение owned loadout.

**Gate:** unowned и wrong-slot нельзя надеть API; два tab не теряют изменения; preview не выдаёт право; grant не auto-equip; нет нулевого XP при outage; RPG hidden оставляет весь учебный функционал.

## G5. Paper-doll proof на существующих источниках

Не генерировать заново BASE/пять сетов. Подготовь реальную alpha базы, wrap region, body masks и measured rig. Сначала два контрастных комплекта ARM-00 и ARM-04: `legs`, затем остальные части. Проверь отдельные части, waist/collar, neutral hands, tail и снятие legs. Сохрани editable masks.

После успешного proof обработай ARM-01/02/03; выполни **20 одиночных parts, 5 full sets, 10 фиксированных mixed outfits**. Установи per-part QA. Автоматически применять кожу/голову из full plates запрещено.

**Gate:** подбор chest не меняет голову/ноги; legs не оставляют вторую голую ногу/повязку; none восстанавливает базу. QA на белом/графитовом/циановом; paint и hide-base сохранены отдельно. Проблемы разметки не объявляй решёнными обычным stacking целых изображений.

Если нужна отсутствующая графика на стыке, изолируй failed part и выдай **один** конкретный repair request. Независимые части и UI продолжают работать. Не завершай визуальный MVP фразой «полные картинки уже похожи».

## G6. Меч / хват / орнамент по готовности

Сначала попробуй извлечь SWD-03 и общий хват из SWORD-POSE-REF. Если скрытых пикселей не хватает — используй условный HAND-R-GRIP prompt или локальный repair, не новый full-body render. Выполни `neutral → grip_back → sword → grip_front`, клинок перед обеими ногами, фиксированное запястье. Missing sword/grip возвращает neutral hand без стирания пальцев.

ORN-01…03 — отдельный `back_ornament` позади головы, без hide-base и смены анатомии. Пока source не получен, renderer path тестируется синтетическим тестовым SVG, явно не финальным артом; production UI использует placeholder.

**Gate:** переключение оружия не меняет bracers/голову; отключение возвращает ладонь; орнамент independent on/off, нет clip. Получение новых PNG потом требует только обработки/manifest update, не переделки сервиса или схемы ownership.

## G7. Полная прогрессия, контент и импорт

Заверши проверенные V/E/R/K/M, first-C insignia, 60+ chronicles, ритм с IANA timezone, corrections/rechecks. Свяжи 25 томов и 58 чертежей с **реальными** ID через content-owner; недостающие условия/семейства/рубрики перечисли. Не придумывай ложные «официальные варианты».

Запусти симуляцию и dry-run импорта; сопоставь прежнюю history с новым ruleset без двойного счёта. Cutover после подтверждения владельца. Старый writer выключается; replay идемпотентен, silent по уведомлениям и не меняет дату активности. Проверка корректного xp/ownership не должна зависеть от готовности арта.

## G8. Итоговая приёмка и сдача

Выполни `11_ACCEPTANCE_AND_TESTS.md`. Собери `docs/crucible/release-report.md`: passed/failed/not_run, реальные команды/версии, screenshots, API flow, baseline regression, content gaps, assets ready/pending, DB restore и rollback rehearsal. Измерь payload/performance, не копируй целевые бюджеты как факты.

Отдельно укажи:

- **Code MVP:** сервисы/контракты/прогрессия/UI работают; отсутствующий контент/арт явно обозначен.
- **Visual MVP:** реальные пять комплектов независимо смешиваются; если какие-то parts pending, visual MVP ещё не принят.
- **Full art catalogue:** все 45 целей приняты; это последующая художественная готовность, не обязательное ожидание перед началом занятий.

Покажи главную 1280×800; задачу с длинной формулой; теорию с возвратом; героя в начальном и mixed outfit; locked предмет с критериями; один реальный reward flow; duplicate/correction; outage recovery; список недостающих артов. Не ставь общий «всё готово», если есть только красивые мокапы.
