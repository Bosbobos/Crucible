# 02. Дизайн-система «Белый Атлас»

**Редакция 3.0.0.** Значения из последнего CRUCIBLE frontend-уточнения сведены здесь и в `styles/crucible-tokens.css`. Старые Golos/Noto, прежняя сланцевая CTA и старое распределение цветов дисциплин не являются параллельным вариантом дизайна.

## 1. Формула интерфейса

Современный светлый интеллектуальный инструмент; благородное фэнтези живёт в персонаже, тканях и отдельных архитектурных иллюстрациях. 80–85% рабочего экрана — читаемые поверхности/контент, 10–15% — иллюстрации, до 5% — золото и яркие отметки. Это композиционный ориентир, не пиксельная метрика.

**Приоритет:** начало самостоятельной попытки → сохранность/понятность данных → paper-doll → художественная цельность → декор. Не делать меню тёмной RPG, жёлтый пергамент, glow-дэшборд или квестовую карту вместо задач. Любой цвет брони допустим без перекрашивания всего приложения.

Текст обычного размера проверять на ≥4.5:1, крупный — ≥3:1; значимые контролы и графические элементы — по соответствующим условиям non-text contrast. Это критерии проверки, не заявление о готовой WCAG-сертификации. Источники S4–S6 в `07_SOURCES_AND_LICENSES.md`. Декоративная border/gold не обязана быть контрастной, но не заменяет видимую границу interactive control.

## 3. Типографика

**Onest**: UI, условия, объяснения, таблицы; локально обслуживаемые latin/cyrillic, веса 400/500/600/700. **Cormorant Garamond**: короткие крупные H1/H2, имя ордена и важного предмета, веса 500/600. Не ставить тонкий декоративный шрифт на маленькие кнопки/ценные данные. Fallback: system-ui и Georgia. Шрифтовых файлов в пакете нет.

| Роль | Размер / line-height |
|---|---|
| Большой H1 | 40/44 desktop, 32/36 mobile |
| H2 | 30/35 |
| H3 | Onest 20/28, 600 |
| Условие, теория | Onest 18/30.6 |
| UI, таблица | Onest 16/24 |
| Подпись | Onest 14/21 |
| Таймер, XP | 16/24 + tabular-nums |

Существующий математический renderer сохраняется; формулы используют его шрифты. Контейнер формулы: padding 16, min-width 0, свой overflow-x, отсутствие вертикальной обрезки. Не уменьшать тело текста ради количества карточек. Не добавлять несколько конкурирующих UI-библиотек/шрифтовых стеков.

## 4. Сетка и геометрия

Spacing: 4/8/12/16/24/32/48/64px. Radius: control 8, card 12, крупная сцена/баннер 16; 999 только чип/аватар. Карточка padding 24 desktop / 16 mobile, border 1, почти без тени. Тень `0 8px 24px rgba(34,43,50,.08)` только drawer/popover/сцена.

- ≥1200px: sidebar 224, основной padding 32, content max-width 1248, главная `minmax(0,1fr) 320px`, gap 24.
- 768–1199px: навигация компактная; вспомогательная колонка ниже; help drawer не сжимает текст до нечитаемости.
- <768px: padding 16, один столбец; доступная существующая navigation либо «Сегодня / Теория / Персонаж / Ещё»; slot toolbar под сценой.

Проверочные viewport: 1440×900, 1280×800, 1024×768, 390×844; zoom 200%. Не масштабировать целую страницу через transform. Первая задача или «Продолжить» видна без прокрутки на 1280×800: при конфликте уменьшается баннер, не рабочие контролы.

## 5. Основные компоненты

### Кнопки и поля

Высота ≥44px, padding-inline 18, radius 8. Primary — белый текст на `--cr-primary`; hover/pressed — определённые в CSS производные, не случайные градиенты. Focus 2px, offset 3px. У поля постоянный label; placeholder его не заменяет. Checkbox/radio имеют достаточную область попадания. Disabled объясняется текстом, а не одним opacity. Не использовать hover как единственный способ доступа.

### SilkBanner

Один неглубокий баннер на «Сегодня»/«Персонаже», max-height 168px desktop. Белая поверхность; ENV-SILK только справа, текст/CTA на сплошной читаемой зоне слева. Нет надписей внутри изображения. Пока ткани нет — та же композиция с чистой поверхностью и тонкой золотой линией. Не подставлять случайный stock или изображение с буквами.

### Эмблема и дисциплинарные знаки

Оригинальная восьмиконечная геометрическая звезда — редкий орденский знак, не паттерн каждого поля. SVG currentColor, viewBox 0 0 64 64, осевой центр 32/32; чередовать 8 длинных и 8 коротких лучей, без заимствованного логотипа. Для маленького UI применять упрощённый линейный вариант.

Руны: LA — направления из начала; CA — приближающиеся линии; PR — разветвление; DS — узлы и рёбра; OD — гладкие траектории. Это original SVG, не генерация, не обещание математического содержания сами по себе. На схеме цвет/линия должны иметь легенду и математический смысл.

### Карточка задачи

ID/название без спойлера метода. Причина: «Повторение по сроку», «Новый вариант», «Проверка переноса». Никаких раскрывающих ответ reward labels в холодном условии. После самопроверки сохраняются понятные исходы «Самостоятельно / С помощью / Разобрал решение». XP — вторичная информация, не сортировка задач по прибыльности.

### Карточка предмета

Aspect ratio 4:5, ширина от 160px; сверху изображение/crop либо собственный SVG-силуэт, снизу имя, слот, статусы. Locked предмет имеет конкретные требования, а не случайный «?». Rarity — небольшой текстовый признак, не цветной фон всей панели.

Различать `locked / owned / equipped`, `qualified / evidence_recheck` и `art_status`. На detail-sheet — «Получено за…» с безопасной evidence ссылкой. «Примерить» локально, «Надеть» явно сохраняет. При missing art надевание owned предмета сохраняется, но рядом предупреждение «Выбор сохранён; изображение готовится». На теле не показывать чужую броню как будто выбранную.

### XP и уведомления

Полоса 6px; числа только из confirmed summary. Одна анимация 300ms после подтверждения, не бесконечный shimmer. Одно агрегированное toast/live-region сообщение на результат; детали по кнопке. Пока character-service не обработал факт — pending, а не выдуманное `+80`. Outage не превращается в «0 XP».

## 6. Движение и доступность

Hover около 120ms, drawer около 180ms, XP 300ms, крупная награда до 450ms однократно по результату. Никаких idle-loop, частиц, вращающегося нимба, автоматического звука и постоянного свечения. `prefers-reduced-motion` выключает несущественное движение. В режиме учёбы декоративного движения вообще нет.

Canvas — картинка, не единственный UI. Дать доступное описание текущего образа, обычный DOM-список слотов, имена, текстовые состояния и keyboard controls. Ошибка загрузки одного изображения не убирает управление. Загрузка имеет фиксированные размеры, не вызывает layout shift.

## 7. Производительность

Canvas перерисовывается по изменениям, не на каждом animation frame. Показывать только нужные изображения; raw PNG — производственное сырьё, не eager-load на главной. WebP с alpha: целевые бюджеты ≤500KB на полноразмерный слой, ≤45KB иконка, ≤350KB фон; реальный размер/качество проверить. Стартовая декоративная загрузка ≤1.5MB, первый инвентарь ≤4MB — цели, не измеренные результаты.

Узнать реальные размеры после нарезки; при превышении сначала убрать невидимые preload и выбрать подходящий resolution. Главная может использовать cached derivative того же принятого loadout, но не отдельного героя. Cache key включает loadout, rig и manifest версии. Шрифты/иконки/ассеты обслуживаются локально; никакой CDN-зависимости для каждого учебного открытия.
