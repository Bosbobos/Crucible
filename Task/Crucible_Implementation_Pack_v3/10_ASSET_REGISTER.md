`BASE-00`, `ARM-03`, `SWORD-POSE-REF` имеют alpha=255 по всему холсту: это непрозрачные изображения с белым фоном. У остальных есть прозрачность, но нет полностью непрозрачных пикселей alpha=255; медиана ненулевого alpha — 253. Это наблюдение, не вывод, что source испорчен. Потребуется осмотр края и материала, без автоматического порогового удаления/усиления alpha.

## 2. Намеренное сопоставление Tier_0 / Tier_1

Кремово-кожаный `Tier_1.png` соответствует историческому ARM-00; зелёный `Tier_0.png` — ARM-01. Сохранён **семантический канон**, а не случайная нумерация загрузок. Эта редакция явно разрешает отличие; агент не переставляет их молча ещё раз. Пороговые условия ранних предметов не менялись.

Утверждение старых уточнений «не использовать Tier_3/image.png» относилось к другим историческим итерациям. Текущие вложения идентифицируются содержимым и hash. Здесь Tier_3 — актуальный белый сет; image.png — отдельный sword reference, не шестой сет.

## 3. Готовность

BASE-00 и ARM-00…04: **генерация дизайна выполнена**, готовность production representations — pending. ARM-05: нет принятого изображения. SWD-03: есть визуальный пример, отдельного слоя/контакта хвата нет. Остальные мечи/щиты/плащи/орнаменты/реликвии/ENV/HALL в этой загрузке отсутствуют; это не заявление, что нигде в других чатах никогда не было кандидатов.

`data/art_manifest.json` задаёт 45 художественных целей, `technical_assets` — условный общий хват. Пять SVG-инсигний создаются кодом, не генерацией. Не искать недостающий файл по случайному похожему имени и не подменять его старой итерацией.

## 5. Что агент должен получить после подготовки

Для BASE — сегментация и rig.approved; для каждого ARM — четыре независимых paint layers и четыре hide-base masks, editable source, registration и QA. Для меча — isolated sword + общий согласованный grip_back/grip_front/neutral-hide. Для орнамента — задний слой без фигуры. Иконки и WebP — производные, не новые ручные изображения.

Нельзя поставить runtime_ready одному полнокомплектному PNG только потому, что его хорошо видно в галерее. Четыре части принимаются раздельно; group-level статус не подменяет slot-level QA.
