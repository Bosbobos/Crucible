# Crucible — пакет модернизации существующего приложения

**Версия пакета: 3.0.0 · 16 ноября 2026.** Действующий ruleset экономики: `crucible-v1` (не перебалансирован). Пакет заменяет прежние разрозненные указания; это спецификация для реализации, **не отчёт о выполненной модернизации**.

## Сначала прочитать

Репозиторий остаётся в старом состоянии: владелец ещё не выполнял эти задания. В этом пакете **нет исходного кода приложения**, результатов его аудита или доказательства существования описанных API. Начинать с реального аудита, затем внедрять изменения в текущий стек. Не создавать новое учебное приложение рядом со старым.

**Целевой результат:** современный светлый математический тренажёр Crucible / «Белый Атлас», с тем же рабочим учебным циклом и отдельным RPG-контуром. Новый `character-service` владеет косметической прогрессией; учебные сервисы владеют учебными фактами. Paper-doll работает в существующем frontend. Нет встроенной LLM, боёвки, валюты, платных улучшений и зависимости сохранения попытки от RPG.

## Что действительно есть сейчас

Есть **одна база, пять полнофигурных источников брони ARM-00…04 и один пример меча в руке**. Все семь PNG включены в `references/` без изменения байтов. ARM-05 не создан/не принят. Готовых вырезанных частей, hide-base масок, утверждённого рига, отдельного меча и hand-grip patch в этом пакете **нет**.

| Канонический ID | Входной файл пользователя | Фактический смысл |
|---|---|---|
| BASE-00 | Base.png | Бронзовый герой с хвостом и короткой белой повязкой |
| ARM-00 | **Tier_1.png** | Кремовый лён / коньячная кожа |
| ARM-01 | **Tier_0.png** | Зелёная стёганая ткань / бронза |
| ARM-02 | Tier_2.png | Серебро / тёмно-синий |
| ARM-03 | Tier_3.png | Белая эмаль / золото |
| ARM-04 | Tier_4.png | Аметист / тёмный металл |
| SWORD-POSE-REF | image.png | Пример меча перед обеими ногами, не готовый слой |

**Tier_0 / Tier_1 сознательно сопоставлены по внешнему виду с каноническим порядком из арт-библии.** Исходные файлы не переименовываются задним числом: точное происхождение и SHA-256 в `data/source_assets.json`. Не сортировать предметы по цифрам upload filename. В пакете используются канонические имена копий.

Base.png содержит короткую повязку и непрозрачный белый фон. Это актуальная утверждённая художественная база; **не требовать ещё одну генерацию тела без ткани**. Сохранить исходник, выделить `modesty_wrap`, скрывать его вместе с заменяемыми областями при реально отрисованном `legs`. Полное пояснение в paper-doll ТЗ.

## Обязательное разделение статусов

- `owned`: право на предмет, вычисляется character-service.
- `equipped`: явно сохранённый выбор пользователя; не доказательство наличия арта.
- `art_status`: `missing | reference_available | processing | qa_failed | runtime_ready`.
- `rendered`: конкретная готовая репрезентация, реально отрисованная сейчас.

Отсутствующий арт не блокирует выдачу предмета, хранение loadout, учебную работу или frontend-реализацию. Но `reference_available` не становится `runtime_ready` без нарезки и QA. Маски отсутствующего/не загрузившегося слоя **не применяются**: иначе исчезнет базовая анатомия.

## Объём и очередность

**Обязательная модернизация сейчас:** отдельный RPG-сервис с рабочей доставкой фактов и корректировками; светлая тема; инвентарь/путь/коллекция; независимые четыре бронеслота; инфраструктура меча и заднего орнамента. Где настоящая графика ещё не прошла QA — честные заглушки.

**Первая художественная очередь:** подготовка существующих пяти комплектов, SWD-03 из примера, общий правый хват, один задний орнамент, кандидат ARM-05. Щиты, мантии, остальные мечи, реликвии и фоны сохраняются в каталоге и получают полные одиночные промпты, но не задерживают учебный релиз.

**Не входит:** развитие одного понравившегося сета, бой, торговля, сетовые бонусы, новые расы/позы, анимация, маски/шлемы, 3D-комната, новый сервис рендеринга. Тяжёлый финальный сет остаётся самостоятельным художественным решением, не перекраской ARM-03.

## Машиночитаемая часть действительно вложена

`data/`: 60 порогов уровней, 59 предметных/косметических определений, 6 рангов, 25 томов, 58 чертежей испытаний, 6 сетов, 5 дисциплин, ID aliases, 45 художественных целей и отдельный условный технический хват. `contracts/`: схемы и примеры целевых контрактов. `styles/`: CSS-токены. `tools/` и `tests/`: проверка пакета, референсная арифметика и тесты. Это не готовый production backend.

**Истина по областям:** числа и таблицы — `data/*.json`; алгоритмы — `03` и `09`; визуальные токены — `styles/crucible-tokens.css`; правила сборки — `CRUCIBLE_01`; статусы исходников — `10` + `source_assets.json`; execution — `06`. Сгенерированные таблицы в MD — читательская проекция данных. При конфликте активных документов добавить failing test, зафиксировать дефект и остановить только спорную часть, а не выбирать молча.

`data/campaign-bindings.template.json` намеренно пуст: реальных problem IDs и рубрик в переданных материалах нет. Это не повод подделывать испытания. После аудита записать настоящие связи либо `BLOCKED_CONTENT`.
