# Crucible — анатомические маски, сменная экипировка, меч и задний орнамент

**Редакция 3.0.0.** Нормативное техническое ТЗ. Сервисное владение перенесено в отдельный `character-service`; этот renderer остаётся frontend-модулем. Ни динамической генерации, ни отдельного сетевого renderer.

## 1. Главный принцип

Для предмета различаются **paint alpha** — пиксели предмета — и **hide-base mask** — области именно базовой анатомии, которые заменяет одежда. Не пытаться сделать каждый готовый PNG непременно шире исходных бёдер. Но маска не создаёт отсутствующую ткань/металл: дыру в слое надо исправлять в слое.

Вся открытая кожа, голова, рога, хвост и незанятые кисти принадлежат `references/BASE-00.png`. Не извлекать их из шести разных переодетых генераций. Текущий BASE имеет короткую повязку: это допустимый вход, не блокер и не повод генерировать нового персонажа.

## 2. Риг

Канонический canvas 1024×1536. Предлагаемый ID `crucible-dragonborn-front-v3`, **статус pending measurement**; наличие имени не означает approved rig. Если в репозитории уже есть проверенный совместимый ID — документировать mapping и сохранить его при неизменной базе. Изменение источника базы/камеры означает новую совместимость, не тихую замену.

Измерить по реальному BASE голову/рога, шею/ворот, оба плеча/локтя/запястья, таз, колени/подошвы, tail root. Координаты `(0.245,0.59)` и аналогичные числа из старых промптов **не использовать как измеренные**. В `data/rig.template.json` anchors намеренно null. Для меча отдельно измерить grip center, ось рукояти, guard, blade tip по текущему sword reference и согласовать с фиксированным запястьем BASE.

Один документированный source-to-rig similarity transform на source plate; не делать независимую произвольную подгонку ног и головы. Все runtime layers сохраняют полный canvas, в UI масштабируются одной общей матрицей. Рамки и hit areas находятся в DOM, не в нарисованном арте.

## 3. Разделение базы без дорисовки скрытой анатомии

Сохранить raw неизменным. После удаления фоновой подложки разметить **непересекающиеся области владения базовыми пикселями**:

| Region | Назначение |
|---|---|
| `head_face_horns` | Защищённая идентичность лица/рогов |
| `neck` | Видимая шея, нижнюю часть вправе перекрывать горжет |
| `torso` | Грудь, живот, бока |
| `upper_arms` | Плечи/бицепсы |
| `forearms` | Предплечья |
| `hand_right_neutral` | Правая кисть, слева зрителю |
| `hand_left_neutral` | Левая кисть, справа зрителю |
| `pelvis` | **Только действительно видимая** анатомия таза вокруг ткани |
| `modesty_wrap` | Имеющаяся короткая ткань из BASE, без выдуманного тела под ней |
| `lower_body` | Бёдра, колени, голени, стопы |
| `tail_back` | Хвост отдельно от ног/таза |

Можно разнести симметричные регионы на left/right. На AA-границах не должно быть двойной непрозрачности или шва: либо отдельная маска объединённого тела, либо нормализованные веса разбиения. Проверить, что сборка всех исходных regions воспроизводит сегментированный BASE до добавления экипировки.

При `legs=none` wrap остаётся видимым. При успешной отрисовке legs скрываются wrap и **только назначенные** заменяемые области таза/ног. Если wrap выделен отдельным `UNDERLAYER-00` crop, это техническая производная того же BASE, не новый генеративный предмет. Под тканью можно оставить неизвестную область: она всегда закрыта wrap либо принятыми legs; обнажённое тело там не требуется.

Нельзя скрыть весь прямоугольник `y > waist`: он срежет хвост/пальцы. `legs` не имеет доступа к маскам рук/головы/хвоста. High collar может перекрыть нижнюю шею, но не лицо/рога. Не рисовать полную шею финальным слоем поверх горжета.

## 4. Формат одного gear part

Каждый `ARM-XX/{chest,shoulders,bracers,legs}` содержит полный canvas RGBA с исключительно предметными пикселями, отдельный grayscale hide-base mask, editable contours и registration metadata. Paint mask может храниться для редактирования, но exported PNG уже содержит итоговый alpha.

**Не умножать alpha дважды:** если alpha экспортированного слоя уже равен source alpha × paint mask, runtime просто рисует его. Повторное применение того же paint mask делает AA-края слишком прозрачными.

`hide_base` хранит значения 0…1 и список `allowed_base_regions`. Для ordinary armor исключены `head_face_horns`, обе кисти и хвост. Boots с закрытыми носками скрывают соответствующие базовые стопы; открытые когти показывают именно базовые когти, не смесь двух генераций.

Пояс и короткие нижние панели всегда legs; chest заканчивается у согласованного перекрытия на талии. Pair shoulders/bracers — один selectable slot, даже если технически нужны несколько render passes. Скрытое основание под соседней частью должно иметь достаточный paint overlap: PNG-нарезка не восстанавливает материал, который в source plate был закрыт чужим наплечником. Такие случаи помечать и локально ремонтировать.

## 5. Render plan и маскирование

Сначала resolver строит **render plan** для выбранного/preview loadout. В него входят только parts, совместимые с rig и реально декодированные вместе со всеми зависимостями. `equipped` не равно `renderable`. Для меча зависимостью является готовый хват; для legs — paint + hide-base.

Пусть Hᵢ — маска i-го **отрисовываемого** предмета, Rᵢ — допустимая область базовой анатомии. Вариант объединения этой версии:

`H(x,y) = maxᵢ [Hᵢ(x,y) × Rᵢ(x,y)]`

`A_visible_base(x,y) = A_base(x,y) × (1 − H(x,y))`.

Для итоговой union-маски использовать pixelwise max или эквивалентную детерминированную операцию. Последовательный `destination-out` каждой полупрозрачной маской не равен max-union и может переистончить край. Объединить маски, затем один раз применить `destination-out` **только к offscreen BASE**, до рисования предметов. См. Canvas API в `07_SOURCES_AND_LICENSES.md`.

Маска никогда не стирает уже отрисованную соседнюю броню, меч или задний орнамент. Проверка holes обязательна: в заменяемом участке должен существовать предмет/запланированное перекрытие, иначе часть не проходит QA.

## 6. Порядок слоёв

UI background вне экспортируемого прозрачного canvas. Базовый порядок render passes:

1. `back_ornament` — целый задний орнамент.
2. `cloak_back` — задняя ткань; никакого вшитого человека/лица.
3. `tail_back` — хвост BASE перед задней тканью согласно текущему виду.
4. `masked_base_body` — видимая база, включая neutral hands, если их не заменяет хват; head уже здесь и не заменяется.
5. `grip_back` — задняя ладонь/часть хвата, только для renderable sword; neutral right hand предварительно скрыта локально.
6. `chest`.
7. `legs` — пояс перекрывает нижний край chest.
8. `shoulders`.
9. `bracers` — манжеты перекрывают естественный wrist seam.
10. `insignia` — малый передний знак в проверенной зоне груди.
11. `sword` — клинок перед бронёй обеих ног, рукоять на/перед задней ладонью.
12. `grip_front` — передние пальцы/когти поверх рукояти.
13. `shield_front` — на левой руке персонажа, справа зрителю.

Это fixed topology, не произвольный z-index пользователя. Если конкретный approved предмет требует локального rear/front split, описать это в manifest и тесте; один selectable item может иметь несколько render parts. Не лечить конфликт бесконечным переназначением глобального z-index, ломая другие наборы.

Обычная head identity сохраняется, потому что источник только BASE, маски/gear paint не затрагивают protected face/horns. Не нужно безусловно рисовать всю head+neck поверх последнего предмета. Отдельный front head pass допустим только по явно проверенной локальной маске, без нижней шеи.

## 7. Меч и локальная замена кисти

Пример `SWORD-POSE-REF` — не доказательство pixel-stable совпадения со всем BASE. Использовать его для положения/дизайна меча и материала хвата, **не для новой головы или целой руки**.

Подготовить один `HAND-R-GRIP-01`: полный canvas с прозрачным окружением, только закрытая правая кисть без bracer/оружия. Разделить на `grip_back` и `grip_front` по фактическому контакту с рукоятью. `hide_neutral_hand` удаляет исходные открытые пальцы в локальном hand region. Wrist transition feathered/AA, но не сдвигает предплечье.

Если часть ладони закрыта мечом в исходном примере и для универсального слоя нужны отсутствующие пиксели — локальный ремонт/условный одиночный prompt. Не тянуть из белого фона недостающие «пальцы». Старую открытую кисть нельзя оставить рядом с закрытой.

Все sword assets используют согласованный grip interface и canvas; resolver не угадывает место по bbox. Конкретные anchors измеряются после приёмки. Направление каноническое: из хвата слева зрителю → перед обеими ногами → нижняя правая часть сцены. Длина как у актуального примера, не старые 0.42 высоты тела; небольшой технический margin позволяет не обрезать остриё.

При `sword=null` вернуть neutral hand. При missing sword либо grip dependencies вернуть neutral hand и не рисовать «плавающий» меч; loadout сохранить, дать art_missing. При смене sword вся зависимая группа (меч/хват/hand-hide) обновляется атомарно. Щит не требует новой кисти, если выбранная фронтальная конструкция полностью перекрывает место крепления; это подтверждается отдельным QA.

## 8. Задний орнамент

Отдельный полный canvas; сам орнамент нарисован целиком, **без выреза в форме головы** и без головы внутри файла. Голова естественно перекрывает его как передний слой. Центр/границы задаются измеренным rig и самим принятым рисунком, не предположением о симметрии морды.

`back_ornament` не имеет hide-base, не изменяет hand/head anatomy, не меняет размер героя и не требует поддержки боевого состояния. На телефоне вся сцена масштабируется целиком. Верхняя форма и рога не обрезаются. Возможные дополнительные display margins одинаковы для всех слоёв, не отдельная подгонка базы под нимб.

## 9. Загрузка, версии и fallback

Каждая сборка имеет generation token/loadout revision. Поздний ответ загрузки предыдущего loadout не должен победить более новый. Декодировать и проверить dependencies до применения масок. Cache key включает asset hash, mask revision, rig, loadout, manifest version и разрешение.

Missing/failed part → не рисовать его и **не применять его hide-base**. Для legs вернуть исходные ноги и wrap; для sword вернуть neutral right hand. Остальные принятые части остаются, если их зависимости удовлетворены. UI показывает сохранённый выбор и перечень отсутствующих representations. Нельзя автоматически заменить выбранный ARM-05 готовым ARM-03 и скрыть факт подмены.

Опциональный last-good-frame fallback маркируется как предыдущий образ; нельзя выдавать его за новое надевание. Manifest обновляется одной публикацией; mixed revisions без compatibility не смешивать. Base background removal pending → честная gallery/placeholder, не fake transparent layering.

## 10. Canvas и производительность

Canvas 2D в текущем frontend (React — если действительно он используется). Offscreen canvas — техническая область, не обязательная новая библиотека/worker. Рисовать по изменению render plan/viewport, без бесконечного requestAnimationFrame. Учитывать devicePixelRatio без изменения канонических координат.

Состояния контролов и доступное описание — DOM. Для export/QA использовать прозрачный композит и отдельные QC-подложки. Все public assets same-origin/корректно CORS-настроены, иначе canvas export может быть недоступен; это проверить в настоящем deployment.

## 11. Paper-doll lab и Definition of Done

`paper-doll-lab`: 9 slot controls (первые 4 доступны по готовности), `none`, source/gallery toggle, paint/hide-base overlays, три фона, 240/360/480px, export contact sheet, сведения о rig/asset versions. Не публичный обход ownership: full catalog testing только dev/test profile, не production equip endpoint.

Обязательные группы проверок:

- BASE reconstructed, wrap visible; ни одна часть без экипировки не потеряна.
- Все 20 частей пяти сетов по отдельности; пять полных образов; **10 фиксированных mixed outfits** из `data/visual_test_cases.json`.
- Head/face/horns pixel-stable там, где их не перекрывает разрешённый воротник; tail не теряется от legs, кисти от bracers.
- Legs не оставляют выступающую базовую ногу и не создают holes; снятие восстанавливает wrap/ноги.
- Sword/grip: порядок перекрытий, правильная правая рука, blade перед ногами, none/restoration, missing dependency.
- Ornament on/off с ARM-00 и ARM-04, все формы в canvas, нет изменения головы/масштаба.
- Image failure, stale async response, manifest switch, refresh/loadout persistence.

До реального QA статус `not_run`. Подготовка пяти источников в этой спецификации **не выполнена автоматически**. Кодовый агент исполняет её на реальных файлах и сохраняет доказательства.
