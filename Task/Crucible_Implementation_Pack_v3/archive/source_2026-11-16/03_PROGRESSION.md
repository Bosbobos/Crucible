# 03. Прогрессия, награды и точные правила

**Правила crucible-v1.** Числа — выбранная игровая модель, не научная оценка знаний и не прогноз результата экзамена. Машиночитаемый источник: `data/progression.json`, `items.json`, `ranks.json`, `cosmetics.json`, `volumes.json`. Если обнаружено противоречие прозы и данных, агент останавливает только спорную часть, добавляет failing test и сообщает расхождение; не выбирает удобное значение молча.

## 1. Два независимых вида прогресса

**Учебный прогресс** — факты самостоятельности, перенос между семействами, отсроченная проверка и результаты пробников. **Путь персонажа** — XP, уровни, ранг, внешний вид. Высокий XP не заменяет успешные испытания; хороший результат входной диагностики не заставляет перечитывать знакомую теорию.

Нет урона, защиты, случайных характеристик, боевых баффов, ускорителей XP, валюты, покупок и функциональных разблокировок. Все предметы косметические. Старый меч остаётся доступен после получения нового. Максимальный предмет не означает, что более простой перестал быть красивым или допустимым.

## 2. 60 уровней

Для целого `L` от 1 до 60:

`total_xp(L) = 100 × (L − 1) + 8 × (L − 1) × (L − 2)`.

Цена перехода `L → L+1`: `100 + 16 × (L − 1)`, пока L < 60. Начало: уровень 1, 0 XP. Уровень определяется максимальным порогом, не превышающим текущий подтверждённый суммарный XP. В `levels` перечислены все 60 порогов, арифметика не делается приблизительно.

| Уровень | Суммарный XP |
|---:|---:|
| 1 | 0 |
| 5 | 496 |
| 10 | 1 476 |
| 20 | 4 636 |
| 30 | 9 396 |
| 40 | 15 756 |
| 50 | 23 716 |
| 55 | 28 296 |
| 60 | 33 276 |

После 60 уровня общий XP продолжает расти. Каждые дополнительные 2 000 XP открывают следующий нумерованный лист «Хроник Конклава»: номер, дата, 3–5 последних содержательных достижений. Это текстовый журнал без новых изображений, reset/prestige и обязательного гринда. Все прежние предметы сохраняются. Не обещать бесконечные уникальные мечи при конечном бюджете арта.

## 3. XP за задачи

### 3.1. Базовые цены

| Уровень задачи | Базовый XP |
|---|---:|
| A — восстановление/базовый приём | 40 |
| B — самостоятельный выбор и экзаменационный ход | 80 |
| C — нетривиальная комбинация/доказательство | 120 |

Классификацию задаёт проверенный контент, не пользовательская кнопка и не агент в текущем диалоге. B/C — редакционные ступени приложения, не официальная шкала Сколтеха. Простой числовой клон сложного примера нельзя превратить в C ради награды.

Коэффициенты результата: самостоятельно — 1.00; с математической помощью — 0.70; разобрал решение и сохранил содержательный вывод — 0.35; пропустил — 0.00. Просмотр решения без разбора не даёт XP. Содержательный вывод — сохранённая собственная формулировка ошибки/приёма, не число символов и не обещание автоматической проверки смысла. Проверка личная; происхождение self-assessment обозначается.

### 3.2. Частичные задачи и самопроверка

Пусть у пунктов веса `w_i`, сумма весов >0. Для самостоятельного/подсказанного пункта коэффициент умножается на оценку по рубрике `q_i` от 0 до 1. Для разобранного пункта при сохранённой собственной заметке вклад равен 0.35, без заметки 0. У пропущенного вклад 0.

`candidate_xp = floor(base × Σ(w_i × contribution_i) / Σw_i)`.

Округлять один раз после суммы. Например, B с двумя равными полностью верными пунктами: один самостоятельный, один с помощью → `floor(80 × (1 + 0.7)/2) = 68 XP`. Одна самостоятельная задача B с рубрикой 90% → 72 XP. Полный разбор B без самостоятельного результата, но с заметкой → 28 XP. Неподтверждённая корректность не превращается в автоматическую оценку ИИ.

### 3.3. Первичное освоение — максимум, а не сумма

Для одной `reward_equivalence_id` хранится наибольший валидный `candidate_xp`. Первая завершённая работа добавляет этот максимум. Более сильная последующая попытка добавляет только разницу.

Пример B: разбор 28 → с помощью 56 → самостоятельно 80. Начисления **28, 28, 24**, всего 80, а не 164. Повторное завершение и редактирование одного результата не создают новую награду.

`reward_equivalence_id` объединяет версии условия и простые числовые клоны. `family_id` обозначает семейство решения и используется для проверки переноса. Это разные поля: две существенно разные постановки могут иметь разные equivalence IDs, но одно семейство. Новая версия Markdown не сбрасывает лимит XP.

### 3.4. Отсроченные повторения

Дополнительный XP за одну эквивалентную задачу возможен только по реальному обязательству scheduler: прошёл установленный срок, с последнего засчитанного освоения/повторения прошло ≥7 суток, результат по рубрике ≥80%, исход самостоятельный либо с помощью. Нажатие «повторить ещё раз» не создаёт подходящее обязательство.

Размер: `floor(base × 0.30 × weighted_quality)`, где weighted_quality рассчитывается по пунктам так же, без reviewed. При 100% самостоятельном результате: **12 / 24 / 36 XP** для A/B/C. Максимум **3** таких начисления на equivalence ID; дополнительные полезные повторения продолжают улучшать учебную статистику без бесконечной игровой эмиссии.

Если scheduler предложил ещё не виденное условие с новым equivalence ID, начисляется первичное освоение, а не первичное плюс повторение. Если в повторной попытке старого условия одновременно улучшился лучший результат, в этой попытке начисляется только разница первичного освоения; повторный бонус переносится на следующее подходящее обязательство. Одной попытке не начислять два конкурирующих вида XP.

## 4. XP за теорию и интерактив

В каждом из 25 томов задано четыре смысловых раздела. Это мета-единицы награждения, не принудительное разрезание любой существующей статьи на четыре равные страницы.

| Действие | XP | Условие |
|---|---:|---|
| Изучить новый раздел полной теории | 12 | Явная отметка + пройденные вопросы самопроверки (ответы сохранены, необязательно все верные) |
| Пройти ядро темы | 8 | Ответы на его короткую проверку и явное завершение |
| Пройти интерактив | 16 | Сохранены прогноз, запуск/изменение параметра и собственное объяснение результата |
| Итоговая самопроверка тома | 12 | Четыре вопроса, минимум три верных; одна собственная итоговая мысль |

Полный читательский маршрут одного тома даёт **84 XP**, не считая печати тома. Все эти начисления одноразовые для стабильного learning unit ID; повторное чтение, возврат, пересоздание страницы и публикация исправленной опечатки не платят заново. Ошибочная самопроверка помогает учиться, не отнимает уже честно заработанные XP за изучение разделов.

Не платить за scroll, открытый таймер, длительность страницы, число токенов агента, создание вопроса или длину заметки. В приложении для одного человека не нужен античит уровня MMO; нужны отсутствие случайного двойного учёта и понятные основания начисления.

## 5. Печати: конкретные достижения

Буквы V/E/R/K — внутренние ключи, в интерфейсе использовать русские названия.

### V · Печать трактата, максимум 25, +40 XP за каждую

Есть два равноправных пути.

**Изучение:** завершены четыре раздела, ядро и интерактив; итоговая самопроверка ≥3/4 и собственная итоговая мысль.

**Подтверждение знакомого:** входная проверка ≥3/4, два свежих независимых решения B или C по этому тому из разных семейств с рубрикой ≥80%, та же итоговая самопроверка/мысль. Перечитывание не требуется, XP за непрочитанные разделы не выдумывается. Итоговая самопроверка даёт свои 12 XP, V даёт 40, задачи дают обычный XP.

Пригодные диагностические задачи могут одновременно стать доказательствами E. Это честное повторное использование одного факта для разных условий, **не повторная оплата самой задачи**. Каждый V отображается на корешке книги и на странице пути.

### E · Печать испытания, максимум 25, +80 XP

Два самостоятельных результата B/C ≥80% в разных семействах одного тома. Обе задачи были свежими до попытки: условие/решение/подробный разбор ранее не открывались. Как минимум один результат — не узнавание уже разобранного шаблона; family IDs и curated mapping проверены контентом. Математические подсказки, ядро или объяснение агента во время попытки исключают independent, но не обычный XP за обучение.

Одна и та же задача может подтверждать только один E-том, зафиксированный в publication mapping. Нельзя автоматически раздать 5 печатей за много тегов одной карточки. Чтение теории до новой холодной попытки допустимо и ожидаемо.

### R · Печать закалки, максимум 25, +80 XP

После E — ещё одно **новое** условие B/C из третьего семейства этого тома, самостоятельно ≥80%, не раньше 7 суток после первого из E-результатов. Это проверка сохранения навыка после паузы, а не календарная награда за ожидание. Дата появляется как часть обычных повторений. При нехватке нового семейства награда остаётся заблокирована из-за контента, а не засчитывается знакомым числовым клоном.

R-задача получает первичный XP; бонус за scheduled repeat к ней одновременно не добавляется. До момента проверки можно заниматься любыми другими темами: искусственный простой не нужен.

### K · Печать зала, максимум 5, +160 XP

Для дисциплины получены все 5 E и минимум 3 R. Пройден её отдельный контрольный комплект из четырёх задач: три уровня B/B+ и одна C; все четыре свежие, минимум три семейства, без помощи; суммарно ≥80% баллов и C-пункт ≥50%. Состав по фиксированной рубрике не меняется после начала.

Веса четырёх задач: 20, 25, 25, 30; C имеет вес 30. Тайминг — ориентир 120 минут, не условие доступа к косметике: качество и отсутствие помощи обязательны, фактическое время фиксируется. Пользователь может выбрать строгий тренировочный лимит отдельно; приложение не отнимает награду за чтение условия медленнее другого человека.

### M · Смешанный пробник, 3 кампанийных результата, +200 XP каждый

После первой K доступен пробник как режим, но доступность режима не требует награды — он может существовать раньше. Для кампанийного M используются три заранее зарегистрированных авторских варианта, шесть задач каждый: по одной от пяти дисциплин и одна составная. Пять B/B+ по 15 баллов и одна C/составная на 25, всего 100. Для M нужно ≥80 суммарно и ≥50% баллов последней сложной задачи, без помощи, все задания свежие. Ориентир 150 минут, отдельно фиксируем реальное время.

Три варианта используют разные family IDs между собой и не совпадают с тренировочными; повтор того же пробника не даёт второй M. Они **не называются официальными вариантами Сколтеха**, а их баллы не превращаются в прогноз поступления. Предыдущий банк holdout не расходовать на обычный XP-фарм.

### Знак высшей пробы · 5 предметов-инсигний, без отдельного XP

Первая свежая самостоятельная C-задача ≥80% в каждой дисциплине даёт её SVG-инсигнию для груди персонажа. Основные 120 XP уже учитывают задачу; дополнительного XP за эту же косметику нет. Так по-настоящему трудная отдельная задача сразу отмечается, не дожидаясь абстрактного счётчика «реши 100».

## 6. Ранги и предметы

Все условия в одной записи `unlock` объединяются через **И**. Поля считают уникальные действительные печати. Уровень — не единственный способ получения предмета, а дополнительный барьер накопленной практики. Нет тайного случайного roll после выполнения условия. Награда доступна сразу после подтверждённого пересчёта; «забрать» отдельно не требуется.

Старт: семь вещей ступени 0, доступные немедленно. Последующие 35 носимых вещей, 9 реликвий, 5 знаков и 3 ауры выдаются по таблицам данных. Карточка закрытого предмета всегда показывает оставшиеся критерии: например, «Уровень 24 / 24; испытания 10 / 12; дисциплины 4 / 5». Ранг не выдаёт собственный повторный XP.

### Классификация предметов

Шесть визуальных ступеней: **Походный → Белый Атлас → Страж связей → Рыцарь пяти залов → Паладин Горнила → Высокий Конклав**. Они отличаются конструкцией, не просто шестью цветами. Названия rarity внутренние, не вероятности выпадения.

Все четыре части брони каждого набора надеваются независимо: нагрудник, наплечники, наручи/перчатки, поножи/сабатоны. Меч, щит и мантия — отдельные слоты. Голова остаётся открытой; шлем не входит в эту версию. Нельзя требовать полный набор для ношения одной новой части.

## 8. Точные чертежи итоговых комплектов K

Контентный агент подбирает/создаёт конкретные условия и публикует их с рубриками. В этом пакете нет притворных «готовых официальных задач». По умолчанию значения/матрицы/параметры выбираются при авторинге, проверяются математически и фиксируются до первой попытки; пользователь не получает случайные неподтверждённые генерации в момент экзамена.

| Зал | Задача 1 / 20 | Задача 2 / 25 | Задача 3 / 25 | Задача 4 C / 30 |
|---|---|---|---|---|
| LA | Ранг/ядро при параметре | Проектор/наименьшие квадраты | Прямоугольное SVD с нулевыми направлениями | Структурная спектральная задача с доказательством или контрпримером |
| CA | Предел с контролем порядка | Интеграл/ряд с параметром и областью | Условный многомерный экстремум | Доказательная оценка/сходимость, где нужно выбрать инструмент |

Машиночитаемые чертежи всех 58 испытаний (25 E, 25 R, 5 K и 3 M) находятся в `data/trial_blueprints.json`. Они не содержат вымышленных готовых задач. Перед связыванием испытания создать `campaign-bindings.json`: конкретные problem/reward_equivalence/family IDs, рубрика, evidence topics, pool=`campaign_holdout`, version. Ни один ID не может расходоваться в двух E-томах; K/M получают свои контрольные условия. Сервис чтения, поиск и MCP не раскрывают ответы/контрольный пул в обычной подготовке.

Если существующий банк не покрывает эти профили, оформить `BLOCKED_CONTENT` с точным недостающим семейством. Нельзя присвоить C обычному примеру, чтобы заполнить таблицу. Отложенный режим геймификации работает на доступном подмножестве; экран честно показывает, почему финальная награда ещё недостижима.

## 9. Баланс на длинный путь

**Нельзя одновременно гарантировать ровно шесть месяцев, не ограничивать сильного пользователя и выдавать награды только за достижения.** Мы выбираем достижения и достаточную ширину работы. Числа рассчитаны на продолжительный маршрут, но быстрый реальный прогресс может завершить его раньше. Ни искусственного календарного запрета на меч, ни обязательного ожидания месяца нет. Пауза R — содержательная отсроченная проверка, а не плата временем.

Базовый расчёт на 26 недель, условно 6 занятий в неделю, до двух часов: около 250 новых полноразмерных условий и 150 назначенных повторений, выборочная теория и 25/25/25/5/3 печати. Это не обещание, что конкретный банк уже содержит все условия, и не персональная рекомендация решать фиксированное число задач в день. Реальная длительность существенно зависит от задачи.

Иллюстративный базовый сценарий:
- 70 A, 150 B, 30 C → потенциально 18 400 первичных XP; средняя итоговая доля 0.95 → 17 480;
- 150 подходящих повторений, среднее начисление 26 → 3 900;
- 20 томов читательским путём + 5 знакомых через диагностику (только 5 итоговых проверок по 12 XP) → 1 740;
- V25/E25/R25/K5/M3 → 6 400;
- всего **29 520 XP**, примерно уровень 56; конечный меч достижим при выполненных качественных условиях, уровень 60 остаётся следующей целью.

Число 26 для повторений — усреднённый вход сценария, не новый тариф; фактические тарифы вычисляются по A/B/C, качеству и помощи. Дневных наград и бонуса за число часов нет. Пробники и K-задачи входят в число новых задач, не добавляются туда ещё раз при подсчёте времени; бонус печати — отдельная премия за сочетание фактов.

Скрипт `tools/simulate_progression.py` показывает консервативный, базовый и интенсивный сценарии. Это статическая арифметическая модель без заявления о научной валидности и без данных реального пользователя. Сравнить с первыми 10 занятиями: median XP на занятие, доля задач/теории, частота крупных наград, упирание в отсутствующий контент. До этого не менять пороги на основании впечатления от одного дня.

Ритм по дизайну: небольшое пополнение XP почти после каждой содержательной работы; небольшая визуальная награда при первом V/E или первой C; части комплектов по сочетаниям V/E/R; высокий меч и тяжёлые латы по большой ширине подготовки. Нет обязательства выдавать предмет раз в ровно N дней. «Поставить ближайшую награду» закрепляет её критерии в UI, но не переобучает scheduler под фарм лёгких задач.

## 10. Серии, отсутствие и известные темы

Главная метрика регулярности — **учебные дни за последние 7**, цель по умолчанию 5. Вторично можно показывать текущую и лучшую последовательность календарных активных дней. Активный день содержит хотя бы один новый учтённый учебный факт: завершённую содержательную попытку, подходящее повторение или новую отмеченную теоретическую единицу. Автоматическое переигрывание старых событий не создаёт сегодняшнюю активность.

Временная зона — явная настройка профиля; день начинается в 00:00 местного времени. Изменение timezone не пересоздаёт события и XP. За серию нет множителя, редкого предмета, XP или наказания; пропуск не удаляет предметы и не снижает уровень. «Ритм» полезен как обратная связь, не как обязательство входить ради таймера.

Известная теория подтверждается диагностикой и задачами. Нельзя требовать открыть 20 страниц знакомого линала для получения V. При этом неподтверждённое «я это когда-то знал» не присваивает E/R/K и C-инсигнию.

## 11. Исправления, импорт и честность

У каждого начисления есть источник, revision, ruleset, amount, command/event ID. Сумма XP — сумма действительных ledger-записей с компенсирующими поправками. При ошибочной самооценке пересчитывается максимум группы и производные печати; лента показывает объяснимый delta. Ошибки в самой работе, пропуски дней и забывание не отнимают накопленные XP. Только исправление неверно записанного факта меняет уже учтённую сумму.

Косметика, уже выданная за действительное на тот момент событие, остаётся доступной; если её основание было именно исправлено/аннулировано, карточка помечается `evidence_recheck`. Повторное подтверждение не выдаёт второй предмет или бонус печати сверх действующего права. Эта мягкая политика не притворяется античитом; приложение личное. Учебная сводка и XP при этом остаются актуальными. Обычное забывание не ретроспективно аннулирует честно полученную награду.

Импорт: старый XP не складывается с заново вычисленным XP той же истории. Выполнить preview переоценки по доступным фактам и подтверждение владельца. Старое число оставить в legacy export. Отсутствующую самостоятельность, семью или время не угадывать. Сомнительные записи сохраняются в учебной истории с provenance, но не получают высокие контрольные печати автоматически.

`ever_granted` для предмета, актуальная квалификация и сумма XP — разные поля. Они позволяют сохранить косметику, честно исправить статистику и не получить награду дважды. Публикация ruleset-v2 не меняет молча всю прошлую экономику: отдельная миграция, preview и тесты.

## 12. Запрещённые способы ускорения

Не выдавать XP за исправление опечатки в собственной карточке, изменение времени, открытие решения, вход в приложение, создание вопроса, переписку с агентом, надевание предмета, подтверждение rank-up или повторную публикацию той же теории. Не умножать XP за стрик и не выдавать бонус XP внутри награды, которая сама зависит от XP: исключить циклическую эмиссию.

Нет обещания измерять понимание по длине текста или автоматически распознавать помощь вне приложения. Внешний агент сохраняет факты/предложения через существующие контракты, владелец подтверждает изменения результатов. Все математические рубрики и основания самопроверки видны пользователю.
