# Crucible — техническое ТЗ: анатомические маски и независимая экипировка

**Статус:** обязательное уточнение действующих инструкций по paper-doll. **Версия:** 1.0, 16.11.2026. **Адресат:** кодовый агент, который развивает существующий репозиторий. **Тип работы:** реализация; не генерация новых персонажей и не новый микросервис.

## 0. Ключевое решение

**Не требовать, чтобы каждый предмет идеально перекрывал все контуры тела BASE-00.** Вместо этого персонаж разбивается на устойчивые анатомические области, а каждый надетый слот имеет **две разные маски**:

- `paint_alpha` — где отображаются настоящие пиксели соответствующего предмета;
- `hide_base_alpha` — какие пиксели **базового тела** нужно скрыть при надевании этого предмета.

Это решает проблему выступающих из-под штанов бёдер, коленей, ног и фрагментов отдельного стартового underlayer. **Маска экипировки не равна маске скрываемого тела:** предмет может выходить за контур тела, а область под ним может скрываться шире его видимого рисунка.

База не перерисовывается при каждом комплекте. **Голова, морда, рога, цвет чешуи, исходная анатомия, поза и хвост всегда принадлежат утверждённому BASE.** Предметы берутся из конкретных готовых комплектов. Никаких динамических вызовов генератора для смены вещи.

Ограничение: **масками можно убрать лишнюю базовую ногу, но нельзя создать отсутствующую ткань, металл или участок брони.** Если в `legs.png` исходного комплекта сохранилась голая нога, либо после скрытия базы образовалась дыра, нужен ремонт самого слоя. Это не решается скрытием ещё большей площади BASE.

## 1. Источники и принятые комплекты

Пять визуальных источников уже получены и доступны для начала работы. Следующие названия — **каноническое сопоставление по содержимому изображений**, а не по исходным случайным именам:

| Канонический ID | Файл-вход | Содержимое | Статус |
|---|---|---|---|
| `ARM-00` | `preview_all-2.png` | Дорожная одежда: лён, тёплая кожа, медные элементы | Reference available, slot QA pending |
| `ARM-01` | `preview_all-3.png` | Глубокая зелёная стёганая ткань, бронзовые усиления | Reference available, slot QA pending |
| `ARM-02` | `preview_all-4.png` | Серебристая конструктивная броня, тёмно-синий текстиль | Reference available, slot QA pending |
| `ARM-03` | `preview_all.png` | Светлая эмаль, матовое золото, синеватые графические акценты | Reference available, slot QA pending |
| `ARM-04` | `preview_all-5.png` | Тёмный металл, платина, аметисты, фиолетовое свечение | Reference available, slot QA pending |
| `ARM-05` | **нет утверждённого файла** | Финальный комплект — художественный поиск не завершён | **Placeholder only** |

**Не использовать** старые `ARM-03.png`, `ARM-04.png`, `ARM-05.png`, `Unknown*.png`, `Tier_3.png`, `Tier4.png`, `image.png`, `изображение.png` как будто они являются утверждённой шестёркой. Это прежние итерации и неудачные попытки. Не подменять `ARM-05` неутверждённым тяжёлым золотым комплектом.

Все пять актуальных файлов имеют 1024×1536 RGBA; это проверенный факт **только о форматах самих полноразмерных изображений**. Их `alpha` и визуальный вид не доказывают, что отдельные слоты уже аккуратно вырезаны или геометрически совмещены. Если в репозитории уже есть лучшие исходные слои/маски этих версий, использовать их как приоритетное сырьё, а превью — для сверки.

**BASE:** перед началом прочитать актуальный канонический BASE-00 в реальном репозитории и сверить с принятыми пятью изображениями. `BASE-00.png` из прежней итерации с белой стёганой одеждой — НЕ подходит. По последнему решению **новый BASE-00 не имеет встроенной повязки вообще**. Для отображения персонажа без надетого `legs` предусмотреть **отдельный нейтральный UNDERLAYER-00** (минимальная короткая ткань; не часть анатомического изображения). Если новой базы в репозитории нет — не подменять; явно заблокировать только точную нарезку базового тела и продолжить UI с временным силуэтом.

## 2. Неизменный rig и канонические координаты

- `canvas`: 1024×1536 px, вертикальный 2:3, все предметы в одних абсолютных координатах;
- `rig_id`: `crucible-dragonborn-front-v2` (допустимо сохранить уже закреплённый ID репозитория с явной миграцией);
- масштаб, расположение рогов, головы, рук, хвоста и ступней фиксируются по **реальным измеренным anchors из BASE**;
- старые приблизительные координаты из предыдущих текстовых промптов не являются измеренной моделью и не должны применяться автоматически;
- для каждого изображения фиксировать `source_hash`, `registration_transform`, `mask_revision`, `rig_id`, `render_priority`, `quality_status`;
- если регистрация исходника требует непропорционального растяжения или изменения анатомии — запретить автоматическую публикацию; разрешена ограниченная однородная регистрация исходника, отдельно документируемая, до извлечения частей;
- изменение BASE приводит к новой версии rig: старые слои без проверки не считать совместимыми автоматически.

## 3. Один раз разделить базового персонажа

Сохранить исходную BASE неизменной, а анатомические маски создать **один раз** в редактируемом виде (SVG path / grayscale PNG + manifest):

| Маска | Назначение |
|---|---|
| `head_neck` | Морда, глаза, рога, голова, шея; остаётся видимой, кроме естественных пересечений воротника |
| `torso` | Грудь, живот, бока, область талии; может скрываться нагрудником |
| `upper_arms` | Плечевая чешуя и бицепсы; показываются, если конкретная броня их не закрывает |
| `forearms` | Предплечья; могут скрываться наручами |
| `hands` | Ладони, пальцы, когти; неизменная основа для последующих предметов/хвата |
| `pelvis` | Таз **без вшитой повязки**; скрывается при `legs != none`. Дополнительный минимальный UNDERLAYER-00 — отдельная опциональная косметика для `legs=none` |
| `lower_body` | Бёдра, колени, голени и стопы; базовая кожа скрывается там, где её заменяет одежда/обувь |
| `tail_back` | Хвост, отделённый от ног и таза; обычно рисуется **позади** экипировки |

Левая/правая стороны допускаются отдельными масками, если этого требуют реальные перекрытия. Не использовать единый прямоугольник `y > waist`: он отрезает хвост и иногда части кистей. В базовых масках отсутствуют случайные куски головы, перенесённые на корпус, и наоборот.

`hands` и `head_neck` не должны исчезать при надевании обычных нагрудников/поножей. Но **не рисовать всю шею поверх любого высокого горжета**: воротник может законно перекрывать нижнюю часть шеи. Для таких пересечений — защищённая маска лица/рогов и осмысленный локальный порядок слоёв.

Для `legs = none` показывать исходные ноги и **отдельный** минимальный нейтральный UNDERLAYER-00; при надетом `legs` он полностью скрывается. Не выдавать нейтральный underlayer за встроенную часть BASE. Хвост в этом переключении **не затрагивается**. Кисти тоже не затрагиваются. Бицепсы сохраняются, пока конкретная shoulder/chest маска не перекрывает их законно.

## 4. Формат каждого предмета

На один комплект и один слот подготовить:

```text
art/armor/v2/ARM-XX/
  source_full.png              # неизменённая копия принятого изображения
  chest.png                    # видимые пиксели грудной экипировки, RGBA 1024x1536
  shoulders.png                # оба наплечника, RGBA 1024x1536
  bracers.png                  # оба наруча, RGBA 1024x1536
  legs.png                     # пояс, штаны, защита таза/бёдер/ног, RGBA 1024x1536
  masks/
    chest_paint.png
    chest_hide_base.png
    shoulders_paint.png
    shoulders_hide_base.png
    bracers_paint.png
    bracers_hide_base.png
    legs_paint.png
    legs_hide_base.png
    editable.svg               # исходные правимые контуры/области
  registration.json
  qa.json
```

На старте используются ровно четыре слота: `chest`, `shoulders`, `bracers`, **`legs`**. Не возвращать название `greaves` для всего нижнего комплекта. `legs` включает **всю нижнюю одежду**, даже если часть видимого рисунка — ткань и кожа, а не металл.

Слой **не должен содержать** вторую голову, хвост, кожу внутри прорезей, фон, остатки старой длинной повязки, встроенный плащ или чужой слот. Примеры: пояс и набедренные накладки — `legs`; наплечники — `shoulders`; видимые элементы груди — `chest`; наручи — `bracers`.

Если исходная картинка содержит сапоги, закрывающие когти, используем именно нарисованную обувь, а базовые стопы скрываем локально. Если когти остаются открытыми, можно показывать **канонические базовые когти** через соответствующую маску; не смешивать две разные формы пальцев из двух рендеров одновременно.

## 5. Алгоритм композиции (не подмена предмета перерисовкой)

Реализовать **детерминированный Canvas 2D compositor** в React (поддерживать обновление только по изменению loadout, rig, viewport или готовности загруженного изображения). CSS-стек `<img>` годится для простой нарезки, но **не решает само по себе задачу удаления базовых пикселей за пределами непрозрачного предмета**. Поэтому в текущей версии нужен отдельный шаг masking.

Нормативный алгоритм:

1. Подготовить базу в отдельном временном canvas, разделив `tail_back`, видимые области тела, защитные части головы и кистей (исходный BASE не менять).
2. Для всех надетых предметов собрать **объединение их `hide_base_alpha`** в разрешённых для каждого слота анатомических областях. В частности, при надетом `legs` скрывается отдельный UNDERLAYER-00, таз и заменяемые части ног, но **не хвост и не кисти**.
3. Применить полученную маску `destination-out` **ТОЛЬКО к соответствующим пикселям базового тела**, до рисования предметов. Не стирать уже нарисованные другие вещи.
4. Рисовать композицию по контролируемому порядку: `background → cloak_back (позже) → tail_back → masked_base_body → chest → legs → bracers → shoulders → protected_head_and_hands → held_objects (позже) → aura_front (позже)`. Превалирование пояса `legs` над нижним краем `chest` задаётся отдельно; если реальная форма требует другого локального порядка, это фиксируемый `overlap_rule` с тестом.
5. Не выводить дважды один и тот же контур чешуи/когтей. `head`/`hands` можно держать в отдельном переднем слое, **кроме** мест, где рукоять оружия или воротник физически должен быть спереди; это будущее дополнение, не повод ломать первую четвёрку.
6. Сохранять визуальную сборку на прозрачном canvas. UI-фон рисуется отдельно, чтобы было возможно проверить артефакты на светлом/тёмном/циановом фоне.

Формула для **только базового** alpha:

`base_visible_alpha(x,y) = base_alpha(x,y) × [1 − combined_hide_base_mask(x,y)]`.

Маски могут иметь полупрозрачную антиалиасинг-границу 0…1. При расчёте `combined_hide_base_mask` учитывать разрешённые анатомические регионы. Это **не** универсальное стирание всех базовых пикселей под любой вещью по всей фигуре.

Одна нарисованная деталь `legs.png` с неполным покрытием не обязана иметь маску `legs_hide_base = 1` на всём прямоугольнике ниже талии: там, где брюки или сапог отсутствуют, необходимо оставить подоснову либо исправить предмет. Если база просвечивает **снаружи** контура полноценных штанов, область скрытия можно расширить за границы `paint_alpha` до настоящей границы одежды, предварительно убедившись в отсутствии дыр.

## 6. Как собирать уже имеющиеся пять комплектов

1. Использовать реально доступные текущие `preview_all*.png` как **канонические полнокомплектные визуальные источники**; не считать их автоматически готовыми `chest/legs`.
2. Для каждого извлечь предметы и создать `paint_alpha`. Не глобально удалять белые пиксели, иначе погибнет белая эмаль ARM-03. Допускается ручная SVG-разметка, маскирование по границам пластин, мелкая зачистка.
3. Для каждого предмета отдельно разметить, какие пиксели **того же BASE** он должен скрывать (`hide_base_alpha`), учитывая положение реальных одежды и брони. Это самый важный новый шаг.
4. Проверить A–E по отдельности на одной базе: `base only`, каждый из четырёх слотов по отдельности, весь комплект вместе. На всех фонах. Дополнительно три смешанных набора: `chest ARM-02 + shoulders ARM-04 + bracers ARM-00 + legs ARM-01` и ещё два, выбранных из противоположных материалов/силуэтов.
5. Неразрешённые небольшие дефекты класть в `qa.json` с `needs_manual_cleanup`. Отсутствие нижней ткани, белые ореолы, испорченный контур, второй хвост или пропавшая кисть — `failed`, не `passed`.
6. Конвертировать принятые PNG-слои в runtime WebP с alpha. Сырые PNG, маски и регистрационные параметры сохранять для редактирования.

**Не делать массовую регенерацию.** Проблема торчащих базовых ног решается масками. Дополнительный арт нужен только если отсутствует сам пиксельный материал предмета или несовместима его геометрия.

## 7. Результат для web и сервисов

- Смена предмета меняет список `slot -> item_id`, маски и источники изображений; не вызывает LLM и не создаёт новую картинку всей фигуры.
- Источник истины о полученных предметах и loadout — существующий progression-модуль `learning-service`. Изображения/маски — версионированные статические ассеты. Не добавлять сервис `equipment-renderer` ради compositing.
- На странице персонажа должны быть независимые переключатели 4 слотов, возможность смешивать ARM-00…04, `none` для каждого слота и отображение условий предметов. Позже оружие/щит/плащ/печать подключаются по отдельной спецификации, пока отображаются реальные заглушки без выдачи несуществующих иллюстраций.
- `ARM-05`: **предметное определение и условие награды могут существовать**, но художественный `art_status=missing`. В инвентаре — спокойная CSS/SVG-заглушка «Иллюстрация готовится». Не подставлять отвергнутый арт, не скрывать прогресс игрока и не утверждать, что финальный слой принят.
- Если владелец уже заработал предмет, отсутствие картинки не отменяет права на него. Отдельные поля `unlocked`, `art_status`, `equipped` не смешивать.
- При загрузочной ошибке одного слоя показывать базового персонажа и остальные принятые предметы, но дать индикатор отсутствующей графики. Не сбрасывать сохранённый loadout без команды пользователя.

## 8. Визуальные тесты и Definition of Done

**Обязательная тестовая страница** `paper-doll-lab`: BASE на трёх переключаемых фонах, четыре слота, выбор любого из 5 комплектов на каждом слоте, кнопки `none`, масштаб 240/360/480 CSS px, возможность снять PNG contact sheet. Не требуется 3D, physics engine, drag-and-drop и новая UI-библиотека.

Проверить:

- [ ] Смена `legs` убирает выступающие базовые бёдра/ноги и отдельный UNDERLAYER-00, но не убирает хвост, руки, голову.
- [ ] Снятие `legs` восстанавливает исходное тело и отдельно подключённый минимальный underlayer; прозрачных дыр нет.
- [ ] Смена `chest` не изменяет морду, рога, хвост, ноги и чужие предметы.
- [ ] `shoulders`/`bracers` можно выключать независимо, не удаляя кожу рук или нагрудник.
- [ ] Исходная нижняя одежда из ARM-00…04 отображается целиком, без «торчащей базовой ноги» и без второй ступни.
- [ ] Десять разных смешанных сочетаний из не менее чем трёх комплектов не имеют крупных дыр/дублирующихся сегментов; найденные конструктивные несоответствия перечислены, а не замолчаны.
- [ ] Head identity pixel-stable: голова не заменяется новым рендером при смене набора.
- [ ] Маски альфы и hide-base можно открыть и отредактировать, преобразование регистрируется, рендер воспроизводим.
- [ ] `ARM-05` отсутствует в рендере как готовое изображение, имеет корректный placeholder, а весь сайт продолжает работать.
- [ ] Нет статуса «все пять совместимы» без фактических интерактивных и визуальных испытаний.

**Готово для выпуска визуального MVP:** новая каноническая база подтверждена; 5 комплектов работают как независимые части; скрытие основы/возврат к основе проверены; финальный предмет честно представлен заглушкой. **Не входит:** генерация ARM-05, анимация, 3D, автоматическая ретопология, возможность надеть одновременно четыре несовместимых полных рендера без нарезки.

## 9. Приоритет выполнения

1. Аудит правильного BASE и пяти принятых референсов.
2. Маски BASE (`tail/head/hands/torso/arms/pelvis/lower_body`).
3. Демонстрация работающего `legs` ARM-00 и ARM-04, включая исчезновение базовой ноги.
4. Расширение до `chest/shoulders/bracers` для двух комплектов, отладка порядка наложения.
5. Обработка оставшихся трёх комплектов и смешанные проверки.
6. Инвентарь/loadout, сохранение, fallback, QA и визуальная интеграция в общий стиль.

Если исходники нового BASE недоступны — сначала п. 1, затем UI с заглушкой; не имитировать полную готовность масок. **Учёба через «Сегодня → задача → теория → результат» не блокируется отсутствием ассетов.**
