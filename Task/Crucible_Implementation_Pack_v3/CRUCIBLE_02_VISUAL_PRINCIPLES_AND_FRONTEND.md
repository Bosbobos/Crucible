# Crucible — frontend и сценарии экранов

**Редакция 3.0.0.** Этот документ описывает композиции и поведение. Единственный набор токенов — `02_DESIGN_SYSTEM.md` / `styles/crucible-tokens.css`; здесь нет альтернативной палитры. Backend RPG — новый `character-service`, не старый progression-модуль learning-service.

## 1. «Сегодня»

Первый приоритет — продолжить незавершённую попытку, затем предложенные задачи с причиной, ближайшее повторение и вопросы к разбору. Неглубокий тканевый баннер не заслоняет рабочее действие. На desktop справа компактная сцена героя, подтверждённые XP/уровень и одна закреплённая награда. На узких экранах блок опускается ниже задач.

Нельзя превращать главную в инвентарь или shop. Не показывать 59 предметов сразу. Статус сохранения учебного результата отделён от обновления RPG. Сбой RPG оставляет эту страницу пригодной для занятия.

## 2. Задача / попытка

Рабочая колонка 700–800px. Условие → собственный ход → помощь/вопрос → завершение. Наверху назад, ID, таймер и автосохранение. Теория справа около 360px только при достаточной ширине; иначе overlay либо отдельный экран с возвращением в тот же draft/attempt/scroll position.

Нет большого героя, полки, нимба или орденского баннера. Кнопки называются «Подсказка», «Открыть ядро», «Завершить», а не ритуалами. При закрытии страницы dirty draft защищён действующим механизмом; модернизация его не ломает.

После подтверждённого учебного save — «Попытка сохранена». До обработки character-service — «Обновляем путь персонажа…». Награда появляется один раз после подтверждения. Нет синхронной зависимости save → reward → success.

## 3. Ядро, теория и лаборатории

Max-width 760px, Onest 18/1.7, почти белая непрерывная поверхность, оглавление/якоря. В контексте помощи — причина открытия и «Вернуться к попытке». Библиотечное чтение без попытки не придумывает фиктивный attempt ID.

Ядро сохраняет мотивирующую задачу, визуальную опору, определения/границы, короткий пример, ловушку и самопроверку. Полная теория не сокращается ради дизайна. Для лаборатории сохраняются прогноз, запуск/параметр, своё объяснение; декоративные эффекты не заменяют её функциональность. Ненаписанная лаборатория — honest content gap.

## 4. Персонаж и инвентарь

Главный художественный экран. Desktop: сцена около 360×540, максимум 420×630, рядом slot controls и список предметов; mobile — последовательная сцена и wrapping toolbar. Полный холст 2:3 масштабируется **целиком**. Никакой отдельной `object-fit:cover` для каждого слоя.

Слоты: нагрудник, наплечники, наручи, нижняя экипировка, меч, щит, мантия, задний орнамент, инсигния. Четыре бронеслота — первый visual MVP. Меч/орнамент — приоритетные следующие представления; все девять slot contracts доступны уже в коде. Маска/шлем не добавляются.

Фильтр слота и состояния, сортировка equipped → owned по ступени → locked. Карточка показывает имя/требования/ownership/art status. Детали имеют независимые действия «Примерить», «Надеть», «Снять». Locked equip API запрещён; preview может показать locked источник без сохранения и с постоянной пометкой.

**Временная галерея:** пять целых изображений можно показать как «Образы комплектов», но это не независимая смена частей. Если слот не обработан, его сохранённое значение и art status видны, а на сцене он не рисуется. Функция «Надеть» owned предмет сохраняет выбор с явным предупреждением; отсутствие готовой маски не превращает право на предмет в ошибку ownership. В галерее opaque белый фон не маскировать под прозрачный.

**Сценарий loading failure:** новый слой загружается до публикации нового render plan; его paint и hide_base принимаются вместе. При неуспехе renderer либо сохраняет последний полный кадр с заметной меткой «Предыдущий образ», либо строит честный fallback без сломавшегося предмета/маски. Запрещено стирать ногу по новой маске, пока PNG новых штанов не загрузился.

Фон однотонный светлый либо принятый ENV-ARCHIVE; не затемняет бронзовое лицо. Предмет не перекрашивает UI. В preview можно отключить орнамент, щит/плащ; они не обязательны для красоты/работоспособности базового персонажа.

## 5. Путь

Шесть рангов и пять дисциплин × пять томов. V/E/R показываются русскими названиями и реальными критериями. Видно различие `не выполнено`, `пересчитывается`, `нет подготовленного испытания`, `основание требует перепроверки`. Отсутствующий контрольный контент не выдаётся за слабость пользователя.

Ранг/сет — разные понятия. Уровень персонажа не прогнозирует поступление. Текст главы доступен по запросу после рубежа, не всплывает посреди формулы. После 60 уровня — Хроники без reset и бесконечных обещаний уникального арта.

## 6. Коллекция

**Девять** позиций, логическая сетка 3×3, девять известных REL-01…09. Начать с DOM/CSS-полок и SVG-силуэтов. ENV-ARCHIVE не обязан содержать нарисованные игровые слоты. Пользователь ставит только owned реликвии, одна вещь — одно место; управление кнопками/клавиатурой, drag-and-drop необязателен.

Без мебели, ресурсов стройки, физики, камеры или 3D-комнаты. Текстовый список коллекции доступен даже при полном отсутствии изображений.

## 7. Режим учёбы и деградация

Настройка скрывает декоративный RPG UI, но не удаляет XP/предметы и не отключает сохранение фактов. Backend продолжает обычную обработку; возврат показа выводит подтверждённое состояние. Settings сохраняются в профильной зоне выбранного владельца по mapping, не в случайном component state.

Не показывать успешные fake values в реальном профиле. Demo/stories используют отдельные fixture IDs и явную метку, не shared production database. CSS placeholders не означают «арт принят», gallery не означает «paper-doll готов».

## 8. Порядок внедрения

G0 audit → общие tokens/components → учебные страницы → gallery/placeholder inventory → API integration → paper-doll lab → четыре независимые части пяти сетов → sword/grip/ornament по готовности арта. Параллельно backend реализует ledger/events; художник генерирует одиночные ассеты. Ни один поток не должен искусственно ждать финального ARM-05.

Acceptance и реальные evidence-файлы — `11_ACCEPTANCE_AND_TESTS.md`. После выполнения обязательных сценариев не расширять геймификацию вместо использования тренажёра.
