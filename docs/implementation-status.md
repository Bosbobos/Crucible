Браузер переносит аварийные черновики, команды с неизвестным исходом и ответы на упражнения по назначению ключа; конфликтующие значения сохраняются.

Подробности последующих проверок — в [записи переименования](rename.md). Исторические результаты ниже относятся к указанным датам; переименование не подтверждает заново готовность P/D.

## Обновление интерфейса 14 ноября

Название — Crucible. Рабочее место разделено на условие и редактор. Конспект читается по исходным разделам: оглавление, положение в тексте, переходы назад/вперёд и отдельная лаборатория. Ответы и раскрытые блоки сохраняются при переходах между разделами в открытом конспекте. Ширина обычных строк ограничена отдельно от формул и таблиц. Черновик располагается рядом от 1280 px, на меньших экранах — над конспектом. В редакторе CodeMirror есть предпросмотр формулы под курсором, парные Markdown/LaTeX-символы и скобки, переход через закрывающий символ и удаление пустой пары с отменой. Markdown-таблицы разбираются как таблицы; названия навыков и другие метаданные поддерживают формулы. Выпадающие списки убраны, варианты выбора отображаются непосредственно на странице. Прежние инфраструктурные свидетельства сохраняют дату 13 ноября.

Первый исполняемый срез готов для локального знакомства. Полные release P и D **не объявляются завершёнными**. Реализация началась с пустой папки проекта: существовавшего приложения и Git-истории здесь не было. Приоритет требований установлен по ADR-003.

## Обновление деплоя 14 ноября

Daily-развёртывание переведено на `scripts/deploy` (POSIX shell + Docker CLI). Make необязателен; host Python/conda/Node для deploy/setup/publish/doctor/firewall не требуются. Bootstrap запускается отдельным Compose до чтения секретов основным стеком, проверяет существующий комплект и не меняет его. Миграции и content-init одноразовые; content-init публикует только в пустую установку и при первом наполнении ждёт каталог в learning. Правила firewall актуализируются до ожидания API и после запуска web, doctor сверяет их с текущими адресами.

Сетевой тест расширен до 26 сценариев, подтверждает REJECT счётчиками в общей сети и настоящий HTTP 200→500→200 при запрете БД. Прежние правила восстанавливаются как после успешного теста, так и после намеренной ошибки; глобальные правила хоста не меняются. Это не автоматический контроллер произвольных ручных Docker-команд: после recreate в обход deploy нужна повторная актуализация политики.

Проверены независимая копия исходников без прежних секретов/volumes, повторный запуск при заглушённых host Python/conda и сохранность 13 файлов секретов, release/catalog_seq и отсутствия добавленных попыток. Проверка опубликованного Git-клона и публикация исходников остаются невыполненными. Датированный отчёт — `docs/obsidian-demo/attachments/deployment-2026-11-14.json`; на том этапе прежние свидетельства failover/restore сохраняли дату 13 ноября. Последующий перенос операторских команд имеет отдельный датированный отчёт ниже.

## Контейнерные операторские инструменты и подробный deploy

Операторские Python-команды переведены в отдельный Linux-образ с Docker CLI. Backup/restore, assessment, SQL isolation, rebuild/replay, экспорт контрактов и резервный импорт вызываются через scripts/operator; обычные тесты и MCP используют более узкие профили без Docker socket. Unit запускается без сети/секретов; integration — в API-сети; Playwright/Node/браузеры — в e2e-образе. Host Python/conda/Node остаются только необязательными developer-инструментами.

Полный инструктаж сначала приводит ручной deploy через консоль с объяснением bootstrap, build cache, volumes, health/dependencies, SQL, публикации, namespaces и iptables. Затем приведены актуальные исходники обёрток с построчными комментариями. В docs/deployment.md находится самостоятельная версия ручной процедуры. Docker socket выдан только явному административному operator; этот профиль не называется sandbox и не является частью веб-приложения.

Проверены 25 Python-тестов, 5 браузерных сценариев, 26 сетевых проверок, реальный Docker stdio MCP (9 tools), SQL isolation/CRUD, backup/restore, rebuild/replay/export/import, PostgreSQL failover/rejoin с verified base backup fallback и RabbitMQ leader failover. Основной стенд во время fault drills не останавливался; 45 исходных файлов секретов сохранены.

Новые результаты контейнерных проверок и даты последующих operator-drills собраны в docs/obsidian-demo/attachments/container-tools-2026-11-14.json. Проверка SDK/контейнерного stdio не заменяет регистрацию MCP в пользовательском desktop-host; полные P/D остаются незавершёнными.

## Остаток до P

1. Зарегистрировать и продемонстрировать MCP в фактически выбранном пользовательском desktop/IDE-host. Клиент SDK это не заменяет.
2. Довести точные response DTO всех HTTP endpoints в OpenAPI: сейчас запросы и события типизированы строго, часть ответов описана общим object.
3. Выделить оставшиеся fault-сценарии MS-10/MS-11/MS-19 и дополнительные XSS/ID/oversize проверки. Текущий набор не заменяет всю исходную AC-матрицу.
4. Опубликовать исходники/архив и проверить именно передаваемую версию. Независимая копия файлов с новой конфигурацией и volumes уже проверена; публичный Git-клон ещё не проверялся.
5. Подготовить демонстрационные скриншоты каждого инфраструктурного сценария для окончательной версии презентации. Текущий шестислайдовый материал содержит UI и фактические результаты, но не все запрошенные преподавателем снимки консоли.

## Остаток до D

Фактическая миграция личной истории в отдельный профиль с ручной проверкой неоднозначных типов, legacy-вопросов/комментариев и неизвестных времён. Пока только backup/dry-run; оригинальный vault не изменён.

Целевой банк по curriculum_manifest: 224 train, 28 holdout, 12 extension, 24 основных модуля и 2 моста. Сейчас опубликованы 57 исходных карточек и 4 заметки; их исходные типы не приравниваются автоматически к слотам v2. Не следует считать slots готовыми карточками или создавать остальные с понижением качества ради числа.

Нужны вложения, расширенный журнал/недельный отчёт, блиц/пробники, поиск, более подробное управление учебной политикой и фокусом, исправление фактов помощи/дат/отдельных частей, UI-восстановление всех конфликтов и длительное личное использование. История HTTP в текущем срезе ограничена 200 попытками, очередь вопросов — 100.

Нужны истечение/отзыв агентских полномочий в эксплуатации, отдельный ограниченный учебный OS-профиль, регулярное продление service credentials, автоматический backup/retention и проверенная внешняя копия. Doctor сообщает отсутствие внешней копии/расписания. Браузерная opaque-сессия требует practice; действующий Bearer API проверяется локально.

SLO за 28 дней, MTBF, статистический MTTR и потребление в длительном daily-использовании не измерены. HTTP MCP/TLS/OAuth не входят в локальный stdio-срез и не заявляются реализованными.
