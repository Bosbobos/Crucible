# Доверительные границы

Доверенные действия оператора: управление Compose, файлами секретов, миграциями, публикацией и backup. Учебный агент имеет scoped HTTP-токены и не получает DSN, ключ подписи или право подтверждать свои предложения. При полном shell-доступе к авторскому репозиторию изоляция скрытых решений отсутствует; нужны отдельные OS-права/mounts.

Один владелец создаётся bootstrap. Пароль хранится Argon2id-хешем только в конфигурации practice. Браузерная сессия — случайный opaque token, в practice_db хранится SHA-256. Cookie HttpOnly/SameSite=Strict, Secure при HTTPS. Проверка CSRF включает origin и session-specific token. Выход удаляет запись сессии. Ограничитель входа хранится в PostgreSQL и не исчезает при сбое Redis.

Proxy проверяет opaque cookie через practice и передаёт короткое EdDSA-подписанное утверждение, audience которого соответствует целевому сервису. Тот проверяет подпись, срок, профиль и scope локально. Входящие X-Session-Assertion перезаписываются. MCP и внутренние клиенты используют отдельные audience/scopes; bearer-проверка proxy не зависит от practice.

Ограничение: при недоступном practice браузерная opaque-сессия не может пройти новую проверку. Read-only Bearer API остаётся доступен с действующим токеном. Агентские токены истекают через 30 дней; немедленный отзыв и автоматическое продление — незавершённые требования D.

XSS-содержимое в условии, черновике и комментарии — данные. ReactMarkdown пропускает raw HTML, безопасно обрабатывает ссылки; KaTeX trust=false; CSP ограничивает внешние источники. Браузерный тест проверил отсутствие активного img/script из черновика. Виджеты выбираются только из двух разрешённых реализаций. Legacy JS никогда не исполняется сервером.

SQL параметризован, роли разделены, CONNECT чужих БД запрещён. У внешнего агента нет универсального fetch URL, SQL, shell или файлового инструмента. Пути API и upstream определяются оператором. Тексты помощи выдаются только после устойчивой фиксации practice; одно и то же command_id не создаёт второй факт.

Приложения работают не от root, с read-only filesystem, cap_drop=ALL и no-new-privileges. Их health не зависит от живого брокера. Исключения: системные контейнеры PostgreSQL/RabbitMQ и отдельный операторский NET_ADMIN probe для сетевых испытаний. Токены и полные личные тексты не включаются в структурированные журналы приложения.

Контейнер bootstrap не имеет сети и получает только запись в `.secrets/`, CHOWN/DAC_OVERRIDE/FOWNER для установки файлов и сохранения владельца каталога на хосте. Это одноразовое операторское исключение; runtime-сервисы остаются non-root. Новые bind-mounted конфигурации имеют 0644 внутри закрытого каталога `.secrets` (0700), чтобы разные non-root UID PostgreSQL/RabbitMQ/API могли читать только явно смонтированные файлы. Пароль владельца и lock имеют 0600. Существующие права и содержимое секретов не переписываются. Bootstrap проверяет комплектность, JSON, подпись/срок клиентских токенов, соответствие ключей и password hash; повреждённая конфигурация требует явного обслуживания.

Tools/content-init получают operator.json read-only для административной публикации и диагностики; собственных DSN им не требуется. Эти операторские полномочия не выдаются учебному агенту. Политика firewall применяется отдельными probe, Docker CLI работает на хосте, socket в приложения и probe не монтируется. Прямое управление Docker в обход deploy требует повторной проверки правил.

Отдельный профиль operator монтирует Docker socket и checkout по совпадающему host-пути для административных Python-процедур. Его socket даёт полный доступ к daemon; cap_drop/read_only не превращают этот профиль в sandbox. Он не запускается по умолчанию и не выдаётся учебному агенту. Unit-тесты работают без сети/секретов/socket, API-тесты — без socket; только явно включённые синтетические fault tests используют operator. MCP-контейнер содержит лишь адаптер/SDK, один scoped credential-файл и API-сеть. Браузерный контейнер получает только synthetic owner password и каталог своих свидетельств, без Docker API.
