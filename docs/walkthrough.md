# Как объяснить систему на одном результате

Пользователь решает задачу P-004. Content уже опубликовал её версию; practice закрепил конкретное условие. Когда пользователь нажал завершение, practice сохранил самооценку и событие в своей БД. Это **локальная транзакция**: либо есть и факт, и outbox, либо нет обоих.

**Outbox** — таблица ожидающих публикации событий, а не ещё одна очередь работы пользователя. Dispatcher отправляет запись в RabbitMQ и ждёт **publisher confirm**. При потере ответа он может отправить событие повторно. Поэтому **идемпотентность** важнее обещания «сообщение никогда не повторится».

**Consumer receipt** фиксируется в одной транзакции с learning-проекцией. Только потом идёт ack брокеру. Повтор не добавляет вторую попытку или минуты. Снимок старой редакции не заменяет новую. **Watermark** — последний непрерывно обработанный номер: увиденный 42 при пропущенном 41 не делает историю полной.

**Redis** хранит ускоренную сводку по известной ревизии. Если Redis выключен, learning читает свои таблицы; план не исчезает. Сам план закреплён в PostgreSQL, поэтому обновление браузера не меняет выбранные задачи.

**Quorum queue** на трёх узлах хранит реплики конкретной очереди. Одного остановленного лидера достаточно для демонстрации перевыборов; два одновременных отказа лишают трёхчленную группу большинства. Три отдельных контейнера без трёх members у очереди не считаются этим сценарием.

**Синхронный standby** подтверждает WAL до успеха записи primary. За сохранность платим доступностью: при потере единственного синхронного standby запись может ждать. **Fencing** гарантирует, что старый primary не останется вторым writable сервером. **Promotion** делает standby новым primary. **Rejoin** возвращает старый узел как реплику после согласования данных, а не просто restart.

**Backup** полезен после проверенного restore в пустой независимый project. Реплика не заменяет backup от ошибки оператора. Все узлы на одном ноутбуке всё равно разделяют питание и диск.

**MCP** — ограниченный интерфейс внешнего агента. Он не вызывает LLM на сайте, не владеет прогрессом и не получает SQL-доступ. Комментарий сохраняется в practice; исправление самооценки остаётся предложением до решения владельца.
